## Agents and flows

Cognigy provides two complementary building blocks for AI-powered conversational experiences: agents and flows. Agents add AI-driven capabilities: they reason, use skills, and act through tools, such as calling APIs, searching knowledge, or sending an email. Flows add the structure and control to orchestrate conversational processes and business logic.

You can use agents and flows independently, because an endpoint can point at either one. You can also combine them to balance AI-driven flexibility with structured execution. This page explains each concept and helps you decide which to use. It is for anyone who designs conversational experiences in Cognigy.

### Agents (beta)

_Agents_ are independent AI-powered entities that use reasoning, skills, and tools to accomplish tasks.

You create, configure, and manage agents independently of individual flows. This separation makes agents reusable across different use cases and lets you develop their capabilities independently of workflow orchestration.

With agents, you can:

- Define the role and behavior of an agent.
- Equip an agent with skills.
- Connect tools that the agent can call, such as APIs, MCP servers, knowledge search, or email.
- Reuse the same agent across different conversational experiences: point an endpoint at it directly, or hand a conversation to it from a flow.

Agents are the recommended approach for building new agent-based applications in Cognigy.

The main building blocks of an agent are:

- [Brand persona](/ai/agents/develop/brand-persona): The voice, tone, and speaking style that you define once and share across agents, separate from what each agent does. Set it on the agent's Configuration tab.
- [Knowledge](/ai/agents/develop/knowledge): What an agent knows about your business. The agent searches your content at run time and answers from what it finds.
- [Skills](/ai/agents/develop/skills): Bundles of instructions and tools for a specific task, such as checking an order status.
- [Tools](/ai/agents/develop/tools): What an agent can do during a conversation, such as call an API, search knowledge, or send an email.
- [Guardrails](/ai/agents/develop/guardrails): The safety settings and data privacy settings that apply to every conversation of an agent.

An agent also has a name, a role, instructions, and a language model.

### Flows

_Flows_ define and orchestrate the execution of conversational processes. A flow consists of [nodes](/ai/agents/develop/nodes/overview) and gives you explicit control over operations, including conditions, branching, data handling, and integrations.

Use flows when you need predefined execution steps, predictable behavior, or explicit control over business logic. For example, processes that involve payments or personal data can require structured execution, validation, and clearly defined steps.

For more information, read the [flows](/ai/agents/develop/projects-and-flows/overview) documentation.

### Flow agents

_Flow agents_ provide agent functionality within a flow. You configure a flow agent's identity, instructions, knowledge, and safety settings on the Flow agents tab of the Flows page. Its job, language model, tools, and memory are set on the Flow Agent node (formerly AI Agent node) in the flow.

Flow agents combine agent capabilities with flow-based execution. Standalone agents offer a more flexible approach: you configure each agent independently, equip it with skills, and reuse the agent across different flows and use cases.

Try agents alongside your existing flow agents to benefit from the capabilities and flexibility of the agents model. Flow agents remain supported, so you can keep running your existing implementations as they are. You can't move flow agents to agents yet, so recreate the settings on an agent. For more information, read the [flow agents](/ai/agents/develop/flow-agents/overview) and [feature parity](/ai/agents/develop/feature-parity) documentation.

### Combine agents and flows

Agents and flows complement each other:

- Use agents for tasks that require AI-driven reasoning and dynamic use of skills and tools.
- Use flows to orchestrate processes that require explicit control, predictable execution, and structured business logic.

Combining them lets you build applications that benefit from both flexible AI-driven capabilities and reliable workflow orchestration. A conversation can move between them in three ways:

- **From a flow to an agent.** Add an Agents node at the end of the flow. It hands the conversation to an agent.
- **From an agent to a flow.** Give the agent the Route to Flow tool. It hands the conversation to a flow.
- **From an agent to a flow and back.** Give the agent the Execute Tool Flow tool. It runs a flow as a tool and returns the result to the agent, which keeps the conversation. For details, see [Bi-directional transfer](/ai/agents/develop/nodes/bi-directional-transfer).

<Note>
Some of these handover options depend on your environment and channel. The Agents node and the Route to Flow tool may not be available in your environment. To show the Route to Flow tool, turn on **Enable Route to Flow tool** in Agent Settings. To show the Agents node, turn on **Enable Agents node** in Agent Settings.
</Note>
