[Large language models (LLMs)](https://en.wikipedia.org/wiki/Large_language_model) are specific types of AI models that are designed for generating humanlike text based on the input and context provided. These models are trained on vast amounts of text data, allowing them to learn patterns, syntax, and semantic relationships between words and phrases.

With LLMs, Cognigy agents can understand and respond to user input in a natural way. These models make conversations more engaging by generating relevant and contextually appropriate responses. LLMs also help manage dialogues and provide multilingual support, enhancing the overall conversational experience for users.

In the Cognigy interface, you can connect to an LLM provider of your choice via API.
Cognigy supports LLM integration with top providers such as OpenAI, Azure, Anthropic, Amazon Bedrock, Google, and Mistral AI. For the full list of supported providers and how to connect each one, see the [LLM providers reference](/ai/agents/develop/gen-ai-and-llms/providers/all-providers).

To integrate an LLM into your conversational design process within Cognigy, follow these steps:

1. [Determine a use case that aligns with your business objectives](#use-cases).
2. [Select your model](#model-types). If you're using a model from an LLM provider, ensure that you have all the necessary API credentials to access the specific LLM you intend to use.
3. Make sure to familiarize yourself with [Cognigy's retry mechanism](#retry-mechanism) in case the model doesn't respond.
4. _(beta)_ Implement a [fallback strategy](#llm-fallback) to enhance the reliability of the model's connection.

## Use cases

Explore key use cases that illustrate how LLMs can be utilized in Cognigy, and learn about the features necessary to implement these use cases:

<AccordionGroup>
  <Accordion title="Automate routine tasks">

    In the Cognigy interface, LLMs help automate repetitive tasks that previously required manual effort from conversation designers:

    - **Generate flows**. LLMs can generate flows based on the provided title and description, helping save time during conversation design iterations. To generate flows, refer to the [Generate flows](/ai/agents/develop/flow-agents/design-time-and-run-time-features#generate-cognigy-resources) section.
    - **Generate lexicons**. With LLMs, you can build a list of keyphrases for the language of your choice based on the title and description of the provided lexicon. To generate lexicons, refer to the [Generate lexicons](/ai/agents/develop/flow-agents/design-time-and-run-time-features#generate-cognigy-resources) section.
    - **Generate intent sentences**. With LLMs, you can build a list of intent sentences based on the title and description of the provided intent. To generate intents, refer to the [Generate intent sentences](/ai/agents/develop/flow-agents/design-time-and-run-time-features#generate-cognigy-resources) section.
    - **Generate adaptive cards**. LLMs can create adaptive cards based on the prompt you provide in the description field for the **Adaptive Card** output type in the [Say](/ai/agents/develop/node-reference/basic/say) or [Copilot: Adaptive Card Tile](/ai/agents/develop/node-reference/agent-copilot/set-adaptive-card-tile) nodes.

  </Accordion>

  <Accordion title="Improve the agent's output">

    The agent's output often requires refinement to meet the high standards customers expect.
    In Cognigy, LLMs can enhance the performance of agents in various ways:

    - **Generate enhanced output**. By using LLMs, agents can produce responses that are more comprehensive, nuanced, and in line with customer needs. This enhancement is important in handling queries that require a level of empathy or complex information processing. To generate enhanced output, add [LLM Prompt nodes](/ai/agents/develop/node-reference/service/llm-prompt) within your flow.
    - **Rephrase the agent's output**. LLMs are good at rephrasing texts while maintaining the original meaning. This capability allows for smoother communication if the original output of an agent lacks clarity or tone alignment. To use this capability, enable AI-enhanced rephrasing in [Say](/ai/agents/develop/node-reference/basic/say#ai-enhanced-output), [Question](/ai/agents/develop/node-reference/basic/question), or [Optional Question](/ai/agents/develop/node-reference/basic/optional-question) nodes by selecting the **Rephrase Output** option in the **AI-enhanced output** section. Also, you can generate dynamic reprompts for incorrect answers via [Question nodes](/ai/agents/develop/node-reference/basic/question).
    - **Train intents and find the right intent**. To enhance agents' understanding of user inputs in various languages, use an [external embedding LLM](/ai/platform-features/nlu/external/external-nlu-intent-recognition). Also, optimize intent classification accuracy by using [LLM-based intent reranking](/ai/platform-features/nlu/external/intent-reranking), which prioritizes and selects the most relevant intent.

  </Accordion>

  <Accordion title="Use retrieval-augmented generation (RAG) with Knowledge AI">

    [RAG (Retrieval-Augmented Generation)](https://en.wikipedia.org/wiki/Retrieval-augmented_generation) is an AI framework that combines data from information retrieval systems with LLMs. This AI framework makes AI-generated content more accurate and relevant by focusing on specific, up-to-date information.

    The [Cognigy Knowledge AI](/ai/agents/develop/knowledge-ai/overview) feature is built on the RAG framework, allowing it to retrieve information from various knowledge bases, including PDFs, Word documents, PowerPoint presentations, web pages, and images. Knowledge AI assists both AI and human agents in providing better responses:

    - **Use Knowledge AI for agents**. Using LLMs integrated into your project, agents can access relevant knowledge sources, including articles from subject-matter experts, frequently asked questions, and diagrams. To create a first Knowledge Store, go to the [Knowledge AI](/ai/agents/develop/knowledge-ai/overview) documentation. Then, retrieve data from the Knowledge Store and improve the agent's output by using the [Search Extract Output](/ai/agents/develop/node-reference/other-nodes/search-extract-output) node.
    - **Use Knowledge AI for human agents**. By retrieving data from different knowledge bases, LLMs reduce the burden on human agents, making information access quicker and more efficient. To let human agents use the knowledge base for solving tasks, add a widget to the Agent Copilot workspace using a [Copilot: Knowledge Tile](/ai/agents/develop/node-reference/agent-copilot/knowledge-tile) node. The widget serves as a search tool, enabling human agents to enter questions and retrieve information from the knowledge base.

  </Accordion>

  <Accordion title="Extract specific entities from user inputs">

    By using LLMs, you can extract specific entities from user inputs, such as product or booking codes and customer IDs.
    For example, if a user input is `I would like to book flight AB123 from New York to London`,
    the LLM can extract the booking code `AB123` from this input.
    This capability allows for dynamic, context-aware responses while improving accuracy and reducing manual data entry.
    To add this feature to your agent,
    add the [LLM Entity Extract](/ai/agents/develop/node-reference/other-nodes/llm-entity-extract) node within your flow.

    </Frame>

  </Accordion>

  <Accordion title="Determine the emotional tone of the conversation">

    Understanding the emotional tone of customer interactions is crucial. LLMs can analyze conversations in real time to determine customer sentiment.
    With Agent Copilot sentiment analysis, LLMs can give insights, enabling human agents to adjust responses for a more effective interaction and improved service quality.
    To let human agents use sentiment analysis provided by LLM,
    add a widget to the Agent Copilot workspace
    using a [Copilot: Sentiment Analysis Tile](/ai/agents/develop/node-reference/agent-copilot/sentiment-tile) node. The widget monitors the conversation and displays the emotional tone (positive, negative, or neutral) of the latest user input in real time.

  <Accordion title="Ensure LLM accuracy with human review">

    Even though LLMs are powerful, there are situations where human oversight is essential.
    Errors in data retrieval or sentiment analysis can occur, especially with nuanced or complex information.
    Human review can help minimize these errors.

    Agent Copilot provides [plug-and-play widgets](/agent-copilot/configure/nodes) in the [workspace](/agent-copilot/index), allowing human agents to review the output generated by LLMs before sending responses to customers.
    This human-in-the-loop approach ensures that wrong or misleading information doesn't reach customers.

## Model types

In Cognigy, you can [bring your own models](#bring-your-own-models) from the offered LLM providers or [use included models](#included-models).

### Bring your own models

If you use models from LLM providers, you can configure them as either [standard models](#standard-models) or [custom models](#custom-models).

#### Standard models

_Standard models_ are predefined models in the Cognigy interface.
To use a standard model, select an LLM provider and model name from the list of [predefined models](/ai/agents/develop/gen-ai-and-llms/model-support-by-feature).
By choosing a standard model, you can ensure that this model is fully compatible with Cognigy features.

After selecting a model, you must enter the API credentials from the [LLM provider](/ai/agents/develop/gen-ai-and-llms/providers/all-providers) that offers this model to get access to its functionality.

#### Deprecations and removals

Standard models that have become outdated and are soon to be removed by the LLM provider are marked with special icons in the Cognigy interface. These icons help you stay informed about changes to the model availability and ensure your agents continue to run smoothly.

| **Icon**                                         | **Meaning**                                                                                                                                                                                                                                                                                                                                                                          | **Recommended Next Step**                                                                                       |
|--------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|
| ![deprecated](/_assets/icons/llms/deprecated.svg)| The LLM provider has stopped developing the model and plans to remove it in the future. Deprecation statuses may vary by provider, for example, Anthropic and OpenAI have `legacy` and `deprecated` statuses, while Microsoft Azure uses only `deprecated`. Cognigy marks a model as `deprecated` after the LLM provider announces plans to stop providing support and updates.   | Select an alternative model by consulting the LLM provider's documentation and switching your agent to it.   |
| ![removed](/_assets/icons/llms/removed.svg)      | The model is no longer available and can't be used. If your agents use this model, they might stop working.                                                                                                                                                                                                                                                                       | Immediately switch to an available model with similar capabilities to prevent agent interruptions or errors. |

#### Custom models

_Custom models_ are non-predefined models in the Cognigy interface. To use a custom model, select an LLM provider and manually enter the model name instead of selecting from a list. While these models may not offer the same level of Cognigy feature support as standard models, they can be helpful when you need a specific version and are familiar with its capabilities. Moreover, if LLM providers release new model versions, opting for a custom model lets you avoid waiting for Cognigy to update its list of standard models.

As with the standard model, you must enter the API credentials for your custom model from the [LLM provider](/ai/agents/develop/gen-ai-and-llms/providers/all-providers).

### Included models

_Included models_ are LLMs and embedding models that NiCE Cognigy provides as part of your license. Their usage is included in the conversation price. You don't need to create a model or enter API credentials. Included models require a new SKU and are available only to installations integrated with NiCE CXone. To set up included models for your organization, contact your customer success manager.

To activate and apply included models, see [Included models](/ai/agents/develop/gen-ai-and-llms/providers/included-models).

## Retry mechanism

If Cognigy encounters issues while trying to connect with LLM providers that don't return a `200 OK` response code,
Cognigy will automatically attempt to reconnect up to three times using a retry mechanism.
This retry mechanism is designed to improve the reliability and stability of the system when using certain Cognigy nodes and features.
By attempting to reconnect multiple times, the retry mechanism increases the chances of successful communication, reduces disruptions and ensures smoother operations within the system.

The following nodes and features are affected by the retry mechanism:

- [LLM Prompt](/ai/agents/develop/node-reference/service/llm-prompt)
- [LLM Entity Extract](/ai/agents/develop/node-reference/other-nodes/llm-entity-extract)
- [Search Extract Output](/ai/agents/develop/node-reference/other-nodes/search-extract-output)
- Question node slot mapping (in case of using [external NLU embedding](/ai/platform-features/nlu/external/external-nlu-intent-recognition))
- [Question node LLM reprompting](/ai/agents/develop/node-reference/basic/question#parameters)
- [Sentiment Analysis](/ai/agents/develop/node-reference/agent-copilot/sentiment-tile)

<Accordion title="Retry mechanism for on-premises">
  The retry mechanism can be customized using environment variables for on-premises installations.
  By adjusting these environment variables, system administrators can fine-tune the retry behavior
  to suit specific performance requirements and network conditions.

| Environment Variable                          | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Default Value |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------- |
| GENERATIVE_AI_RETRY_OPTIONS_NUMBER_OF_RETRIES | Determines the number of retries after the first attempt before failing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | 2             |
| GENERATIVE_AI_RETRY_OPTIONS_MIN_TIMEOUT       | Determines the timeout between retries to avoid rate limiting.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | 50ms          |
| GENERATIVE_AI_RETRY_OPTIONS_MAX_TIMEOUT       | Determines the maximum timeout between retries.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | 50ms          |
| GENERATIVE_AI_RETRY_OPTIONS_FACTOR            | Determines how long a retry timeout will last. The timeout duration increases with each subsequent retry. If the factor is greater than 1, the timeout duration will increase exponentially. This means that with each subsequent attempt, the waiting time won't just increase by a constant amount, but rather by multiples. For example, if the initial timeout is 1 second and the factor is set to 2, then the second timeout will be 2 seconds, the third will be 4 seconds, the fourth will be 8 seconds, and so on.             | 1             |

</Accordion>

## LLM fallback

In addition to the [default retry mechanism](#retry-mechanism) that applies to all models, you can configure an [LLM fallback](/ai/agents/develop/gen-ai-and-llms/fallback) for a specific model.
Create a fallback model to ensure your agents continue working if the main model fails.
Set a threshold for failed requests to trigger the fallback, specify its active duration, and enable notifications.
Note that creating fallbacks for embedding models isn't supported.
