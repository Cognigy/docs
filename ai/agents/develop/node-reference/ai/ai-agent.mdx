## Description

<Warning>
As of Cognigy 2026.18.0, the **Maximum Completion Tokens** and **Temperature** parameters are deprecated. For models that don't support these parameters, activate the **Ignore deprecated parameters** toggle to exclude them from the request to the LLM provider. Otherwise, the request to the LLM provider might fail. If you plan to use these parameters, migrate them to the [Custom Options section](#custom-options) and activate the **Ignore deprecated parameters** toggle. Otherwise, Custom Options might not override them for every provider and model combination.

For example, OpenAI models such as `gpt-5`, `gpt-5.1`, and `gpt-5.2` don't support these parameters. Similar models from other LLM providers might also not support these parameters. Check your LLM provider's documentation for model-specific support.
</Warning>

The Flow Agent node assigns a job to a flow agent, provides instructions and tools for that job, and access to the knowledge the flow agent can use when holding a conversation with a user.

To configure this Node, follow these steps:

1. [Define a flow agent job](#parent-node).
2. [Define the tool actions to perform this task](#child-nodes).

<Tip>
In comparison to the [LLM Prompt Node](/ai/agents/develop/node-reference/service/llm-prompt), the Flow Agent node includes the [flow agent persona](/ai/agents/develop/persona) in the prompt. If you want a more direct approach to control the prompt from the Node editor, use the LLM Prompt Node.
</Tip>

## Limitations

- By default, the number of transcript turns is set to 50. In the Flow Agent node, this number is fixed and can't be adjusted, unlike in the [LLM Prompt](/ai/agents/develop/node-reference/service/llm-prompt#advanced) and [Get Transcript](https://docs.cognigy.com/ai/agents/develop/node-reference/service/get-transcript#parameters) Nodes, where customization is possible.

    **Forcing Model Versions**

    You can force the Flow Agent node to use a specific model version by including it in the Custom Options.
    This means that the Flow Agent node uses the specified version of the language model instead of the default or any other available versions. This gives you more control over the behavior of the Flow Agent node, ensuring it uses a specific model version for generating prompts or responses.

    You can use any models from [LLM providers](/ai/agents/develop/gen-ai-and-llms/providers/all-providers) supported by Cognigy, including those not yet directly integrated. However, you can only replace a model with another from the same provider.

    Consider an example with Anthropic as the LLM provider:
    
    You can force the Flow Agent node to use the model version `claude-opus-4-8-20260101`, despite the LLM resource defaulting to the `claude-sonnet-4-6` model:

    1. [Create an Anthropic LLM resource](/ai/agents/develop/gen-ai-and-llms/providers/anthropic) for Claude, for example, `claude-sonnet-4-6`.
    2. Create a Flow and add a Flow Agent node to it.
    3. In the Flow Agent node, select the model `claude-sonnet-4-6` from the **LLM** list.
    4. In the **Custom Model Options** field, add `{ "model": "claude-opus-4-8-20260101" }` to force the use of the `claude-opus-4-8-20260101` model.
    5. Click **Save Node**.

    The Flow Agent node then uses the `claude-opus-4-8-20260101` model.

    For more information on supported models, see:

    - [Aleph Alpha models](https://docs.aleph-alpha.com/)
    - [Anthropic models](https://docs.anthropic.com/claude/docs/models-overview)
    - [Azure OpenAI models](https://learn.microsoft.com/en-us/azure/ai-services/openai/concepts/models)
    - [OpenAI models](https://platform.openai.com/docs/models)

    **Forcing JSON Output on Amazon Bedrock and Anthropic**

    For [Amazon Bedrock](/ai/agents/develop/gen-ai-and-llms/providers/amazon-bedrock) and [Anthropic](/ai/agents/develop/gen-ai-and-llms/providers/anthropic) models, add the `output_config` parameter to the **Custom Model Options** field to force the model to return a specific JSON response.

    For example, to force the model to return JSON matching a specific schema:

    ```json
    {
      "output_config": {
        "format": {
          "type": "json_schema",
          "schema": {
            "type": "object",
            "properties": { "answer": {} },
            "required": ["answer"]
          }
        }
      }
    }
    ```

    With this configuration, a prompt such as "What is 1+1?" returns a response like `{"answer": 2}` instead of plain text.

### Avoiding infinite loops when tool choice is required

When **Tool Choice** is set to **Required**, the model must call a tool on every turn. After a tool branch executes and a [Resolve Tool Action](/ai/agents/develop/node-reference/ai/resolve-tool-action) Node returns the result to the Flow Agent node, the model still can't respond with plain text. Instead, it must call another tool. If every tool branch loops back through a **Resolve Tool Action** Node, the flow agent keeps calling tools without ever producing a response. This loop continues until the Flow times out and can consume a large number of tokens.

<Warning>
Avoid setting **Tool Choice** to **Required** unless your use case requires the model to always call a tool. If you do use this setting, ensure that at least one tool branch exits the loop without passing through a Resolve Tool Action Node.
</Warning>

To prevent an infinite loop, use one of the following approaches:

<AccordionGroup>
  <Accordion title="Option 1: Change tool choice to auto">
  
  Set **Tool Choice** to **Auto** unless your use case strictly requires the model to always use a tool. With **Auto**, the model calls a tool when relevant and returns a plain-text response when the tool isn't needed, allowing the Flow to exit normally.
  </Accordion>

  <Accordion title="Option 2: Add an exit tool">
  
  Keep **Tool Choice** set to **Required** and add a dedicated tool that the model can call to end the loop. This tool branch must not include a Resolve Tool Action Node, so execution doesn't return to the Flow Agent node. Instead, the branch must end with a Say Node or another output Node that produces the final response.
  
  Example exit tool configuration:
  
  | Field       | Value                                                                                                          |
  | ----------- | -------------------------------------------------------------------------------------------------------------- |
  | Tool ID     | `finish_response`                                                                                              |
  | Description | `Call this tool when you have gathered all the information needed and are ready to respond to the user.`       |
  
  The resulting Flow structure looks like this:
  
  ```text
  Flow Agent node (Tool Choice: Required)
  ├── search_knowledge → Resolve Tool Action → [returns to Flow Agent node]
  └── finish_response  → Say Node            → [end of Flow, no Resolve Tool Action]
  ```
  
  The model calls `search_knowledge` one or more times to gather information, then calls `finish_response` to exit the loop and deliver the response.
  </Accordion>
</AccordionGroup>

## Get flow agent jobs and tools via API

You can retrieve all job configurations and associated tools for a specific flow agent via the Cognigy API [`GET /v2.0/aiagents/{aiAgentId}/jobs`](https://api-trial.cognigy.ai/openapi#get-/v2.0/aiagents/-aiAgentId-/jobs) request. The response includes each job's configuration details and a list of available tools.
