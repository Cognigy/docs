Access to Cognigy allows you to log in to and log out of Cognigy.

## Prerequisites

- You need to have a Cognigy account.

## Login

### Limit active login sessions

By default, there's no limit to the number of sessions you can start in Cognigy across different browsers. However, you can set a limit for on-premises installations. Set the `REFRESH_TOKEN_MAX_AMOUNT_PER_USER` variable in `values.yml` to the number of active sessions you want to allow. For example, if you want to allow only one active session, set `REFRESH_TOKEN_MAX_AMOUNT_PER_USER=1`.

### Log in to Cognigy

You can access Cognigy's login page through the following login URL:

```txt
https://<frontend-url>/login
```

`frontend-url` depends on your installation:

- For on-premises installations, `frontend-url` is a domain you defined to run Cognigy.
- For SaaS installations, `frontend-url` is provided to you during deployment.

For example, `frontend-url` for Cognigy's trial environment is `trial.cognigy.ai`, and the login URL is `https://trial.cognigy.ai/login`.

### Reset password

1. Go to the login page and click **Forgot password?**.
2. Enter your email in the **Email** field.
3. Click **Send Link**.

You receive an email with instructions to reset your password. You need to choose a password according to the [password policy](/ai/administer/access/management-ui#change-password-policy) your admin set up.

### Account lockout

Your account is locked after 5 consecutive failed login attempts by default. Failed attempts more than 24 hours apart don't count as consecutive, and a successful login resets the count. Administrators can change this limit or set it to `0` to turn off the lockout in the [password policy](/ai/administer/access/management-ui#change-password-policy).

When your account is locked, the login page still shows `invalid email or password`, even if you enter the correct password.

Locks and unlocks are recorded in the audit log as `lockUser` and `unlockUser`.

The lockout doesn't apply to:

- The last active administrator of an organization.
- Users who sign in only with SSO.

When your account is locked, you receive one email with the subject `Your Cognigy account is locked` and a link to reset your password. Further failed attempts don't send more emails.

To unlock an account, use one of the following options:

- Use the link in the email to set a new password.
- Use **Forgot Password?** on the login page, as described in [Reset Password](#reset-password).
- Ask an administrator to click **Reset failed login attempts** or use **Set password** in the user details in the Admin Center. For details, see [Access Control](/ai/administer/access/admin-center/access-control).

### Multiple organizations

In Cognigy, you can be part of more than one [organization](/ai/administer/access/management-ui#manage-organizations). Each organization has a different login URL. For each organization, the login URL follows this pattern:

```txt
https://<frontend-url>/login?organisationId=<organization-id>
```

The `organization-id` parameter is a unique identifier with 24 characters that identifies an organization in Cognigy.

<Warning>
  If you're part of more than one organization, you need to include `organisationId` in the login URL. Otherwise, the login fails.
</Warning>

#### Email notification for failed login


If your login fails because you didn't include `organisationId` in the login URL, you receive an email with login links for each organization you belong to.

The login links in the email redirect you to the Cognigy login page with the `organisationId` parameter of the respective organization in the URL.

## Logout

### Log out of Cognigy

To log out of Cognigy, open the user menu at the bottom of the navigation menu and select **Logout**.

### Automatic logout

The automatic logout feature allows you to set an inactivity period for users in your organization. If a user remains inactive longer than this period, they are automatically logged out.

By default, the inactivity period is 15 minutes. However, you can set a limit for on-premises installations. Set the following variables in `values.yml`:

- `FEATURE_ENABLE_AUTO_LOGOUT_ON_INACTIVITY=true`.
- `AUTO_LOGOUT_IDLE_TIME_IN_MIN` to the inactivity period you want in minutes.
