The *yes/no intents* feature uses machine learning to detect `yes` and `no` responses similarly to traditional intent matching, enabling a more natural and fluent conversational experience. A model trained with a small set of example sentences recognizes various `yes` and `no` phrases, enhancing an agent's ability to understand user confirmations or denials.

The [Question](/ai/agents/develop/node-reference/basic/question), [Optional Question](/ai/agents/develop/node-reference/basic/optional-question), and [Code](/ai/for-developers/code/overview) nodes support the yes/no intents feature.

## Key benefits

- **Improved natural language understanding**. Unlike the earlier [confirmation words](/ai/platform-features/nlu/intents/confirmation-words) feature, which required manual synonym definitions, yes/no intents use a preinstalled vocabulary that can be expanded. This approach makes it easier to detect diverse expressions.
- **Enhanced user experience**. Yes/no intents enable agents to respond accurately to a broader range of affirmative or negative responses, reducing misunderstandings and improving conversations.

## Restrictions

- Yes/no intents don't support the Intent Trainer.
- Yes/no intents don't provide traffic light feedback during training, which may limit visibility into model performance.

## How to use

To set up this feature, do the following:

<AccordionGroup>
  <Accordion title="Select a locale">
    Each locale has its own yes/no intents model, requiring separate training. The Universal locale includes English examples, but you should add more examples for better accuracy in other languages.

    To configure a locale, do the following:

    <Tabs>
      <Tab title="GUI">
        1. To see the project's configured locales, go to **Manage > Localization**.
        2. Select the locale and click ![Menu icon](/_assets/icons/black-and-white/vertical-ellipsis.svg), then select **Edit Yes / No Intents**.
        3. In the **Edit Yes / No Intents** pane, configure the following intents for the current locale:
            - **Yes Intent**. By default, the setting is activated. When you deactivate the setting, the intent is excluded from the build.
            - **No Intent**. By default, the setting is activated. When you deactivate the setting, the intent is excluded from the build.
            - **Reject Intent**. By default, the setting is activated. You need to add examples manually. When you deactivate the setting, the intent is excluded from the build.
        4. Optionally, add [rules](/ai/platform-features/nlu/intents/rules) for the Yes and No intents.
        5. Click **Save & Build** to build a model. The yes/no intents model is always built when you edit and save settings.
      </Tab>
      <Tab title="API">
                To create or update sentences for a specific locale, use the following Cognigy API requests:
                - **Create**. [POST /v2.0/locales/{localeId}/yesnointents/{intentId}/sentences](/api-reference/yesno-intents/create-a-sentence)
                - **Update**. [PATCH /v2.0/locales/{localeId}/yesnointents/{intentId}/sentences/{sentenceId}](/api-reference/yesno-intents/update-a-sentence)
      </Tab>
    </Tabs>
  </Accordion>
  <Accordion title="Use yes/no intents for specific or all flows">
    Select how you want to apply the yes/no intents feature: to the entire project or to the selected flow.

  <Tabs>
    <Tab title="Project-level settings">
              To use yes/no intents for all flows, do the following:

              1. In the navigation menu, go to **Manage > Settings**.
              2. On the **Settings** page, click **NLU Settings**.
              3. In the **General Flow Logic** section, select one of the following options from the **Yes/No Logic** list:
                  - **Yes/No Intents - with extended rules**. Evaluates the standard confirmation words logic first. If the standard confirmation words logic fails to determine the input type, the yes/no intents model is evaluated.
                  - **Yes/No Intents**. Evaluates the yes/no intents logic for every user input. The standard confirmation words logic is only used as a fallback when no Yes, No, or Reject intents from the yes/no intents model are triggered.
              4. If you selected **Yes/No Intents - with extended rules** or **Yes/No Intents**, configure **Yes/No threshold**. The **Yes/No threshold** slider sets the minimum score required for yes/no intents to trigger. A Yes, No, or Reject intent is only triggered if the intent score is greater than or equal to this threshold. This value applies to yes/no intents models for all locales. You can change this value for a specific flow.
              5. Click **Save** to apply settings and build a model. The yes/no intents model is always built when you edit and save settings.

              If you've configured settings at the project level but want to change them for certain flows, go to the flow-level settings.
    </Tab>
    <Tab title="Flow-level settings">
      By default, all flows inherit the **Yes/No Logic** and the **Yes/No threshold** settings from the project-level configuration. You can override these settings for a specific flow.
      To use yes/no intents for a specific flow, do the following:

      1. In the navigation menu, go to **Design > Flows** and open the flow.
      2. Go to the **Settings** tab, then select **Configuration**.
      3. In the **General Flow Logic** section, select one of the following options from the **Yes/No Logic** list:
          - **Yes/No Intents - with extended rules**. Evaluates the standard confirmation words logic first. If the standard confirmation words logic fails to determine the input type, the yes/no intents model is evaluated.
          - **Yes/No Intents**. Evaluates the yes/no intents logic for every user input. The standard confirmation words logic is only used as a fallback when no Yes, No, or Reject intents from the yes/no intents model are triggered.
      4. If you selected **Yes/No Intents - with extended rules** or **Yes/No Intents**, activate **Thresholds** and adjust the **Yes/No threshold** slider. The slider sets the minimum score required for yes/no intents to trigger. A Yes, No, or Reject intent is only triggered if the intent score is greater than or equal to this threshold. This value applies to yes/no intents models for all locales in the current flow. The **Thresholds** setting also applies to the **Intent Threshold** slider.
      5. Click **Save changes** to apply settings and build a model. The yes/no intents model is always built when you edit and save settings.
      </Tab>
    </Tabs>
  </Accordion>
</AccordionGroup>

## How to test

Check if the yes/no intents feature works as expected via the [Interaction Panel](/ai/agents/test/interaction-panel/overview):

1. In the existing flow, open the Interaction Panel by clicking the chat icon (<img src="/_assets/icons/black-and-white/interaction-panel.svg" width="16" height="16" alt="Chat icon" />) in the upper-right corner of the page.
2. Run a flow.
3. On the **Info** tab, select **Input** to view the Input object in JSON format. In the `yesNoIntentResults` object, you'll see the result of the yes/no intents model evaluation.

  <Accordion title="FAQ">
    **Q1**: What happens if the **Yes/No Logic** setting is set to **Yes/No Intents**, but both `yes` and `no` intents have been individually deactivated in the locale settings?

    **A1**: The standard confirmation words logic is used.

    **Q2**: Are yes/no intents independent of standard intent scoring?

    **A2**: Yes, the yes/no intents are completely independent of standard intent scoring (`input.intentScore` or `input.nlu.intentMapperResults`). They specifically find the types `nAnswer` and `pAnswer` within the flow. These types are used for the **Yes/No** type in [Question nodes](/ai/agents/develop/node-reference/basic/question) and for [confirming intents](/ai/platform-features/nlu/intents/overview), similar to [confirmation words](/ai/administer/access/project-settings#nlu-settings).

    **Q3**: How are yes/no intents evaluated when the Execute Flow node is used with and without the **Parse Intents** setting activated?

    **A3**: Yes/no intent scoring behavior differs only if the yes/no intent settings are different in the two flows.

    For example:

    Prerequisites:

    - Flow A has **Yes/No Intents** and only one node, which is an Execute Flow node that executes Flow B.
    - Flow B has **Yes/No Intents - with extended rules** and one Say node.

    Scenario 1:

    1. The **Parse Intents** setting is deactivated in the Execute Flow node of Flow A.
    2. When the user sends `yes` in Flow A, the Yes intent is triggered in Flow B.
    3. Flow B inherits the **Yes/No Logic** setting from Flow A.

    Scenario 2:

    1. The **Parse Intents** setting is activated in the Execute Flow node of Flow A.
    2. When the user sends `yes` in Flow A, the Yes intent isn't triggered in Flow B.
    3. Flow B uses its own **Yes/No Logic** setting.
  </Accordion>

## Example

Imagine a user interacting with an agent in a Star Wars quiz:

**Without yes/no intents**:

```txt
User: Hello! 
Agent: Do you want to play the Star Wars quiz?
User: Why not
Agent: Not sure I understood this correctly. Try again.
```

**With yes/no intents**:

```txt
User: Hello! 
Agent: Do you want to play the Star Wars quiz?
User: Why not
Agent: Let's start!
```
