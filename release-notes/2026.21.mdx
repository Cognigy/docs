</Warning>

## 2026.21.0

### Cognigy

**Released** October 12, 2026

#### Features

##### New Models by Mistral AI

Added support for [Mistral AI's](/ai/agents/develop/gen-ai-and-llms/providers/mistral) `ministral-14b-latest`, `ministral-8b-latest`, and `ministral-3b-latest`. These models are compact and offer a strong performance-to-cost ratio. Use `ministral-3b-latest` for fast, lightweight tasks and `ministral-14b-latest` when you need higher accuracy at a low cost.

#### Improvements

- Added the A2A Agent Node as a child Node of the [LLM Prompt Node](/ai/agents/develop/node-reference/service/llm-prompt#a2a-agent), making it easier to use A2A capabilities within LLM-based workflows
- Added `API Key` to the Performed By column and filter on the [Audit Events](/ai/administer/access/admin-center/audit-events) page to make changes made through the Cognigy API easier to track

#### Bug Fixes

- Fixed the issue where the Progress Message field in the Call A2A Agent, Call MCP Tool, and Execute Workflow Tool Nodes had no effect except on A2A Server Endpoints. Now, the field is removed from these Nodes, and the Call MCP Tool and Execute Workflow Tool Nodes no longer send status updates to A2A clients
- Fixed the issue where restoring a Snapshot broke messaging in conversations handed over to a human agent because the handover provider received a new ID. Now, the provider keeps the same ID during restore
- Fixed the issue where OData Analytics requests were rejected with `429 Too Many Requests` during normal reporting use
- Fixed the issue where follow-up requests after an AI Agent tool call to Google Gen AI models, such as `gemini-3.5-flash`, contained the tool-call ID instead of the tool name
- Fixed the issue in streamed OpenAI and Azure OpenAI Responses API answers containing two text messages separated by a tool call. The response no longer repeats the first sentence or drops the first word of the second message
- Fixed the issue where calls to the Gemini 2.5 model family failed with `Value is not a valid number: NaN` when the model returned an empty answer
- Fixed the issue where API requests were slower because the permissions cache wasn't used after a version mismatch between services, so permissions were recomputed on every request
- Fixed the issue for on-premises installations where `service-api` logged many `A cacheClient.get call has errored` error messages. The system loaded the data from the database instead of the cache, so a login or permission check could take longer. Now, the system reads user data from the cache correctly, and the error messages no longer appear

### Cognigy Agent Copilot

**Released** October 12, 2026

#### Improvements

- Added the End Session On Handover Close toggle and the Session TTL On Handover Close field to the [Copilot section](/agent-copilot/configure/copilot-section#parameters) of the Endpoint settings. This improvement lets human agents trigger follow-up actions in the Agent Copilot Flow after resolving a conversation without keeping it open
- Added the Enable Branding toggle to the [Copilot section](/agent-copilot/configure/copilot-section#parameters) of the Endpoint settings. This toggle lets you remove the `Powered by Cognigy.AI` branding to better align the Agent Copilot workspace with your organization's branding
