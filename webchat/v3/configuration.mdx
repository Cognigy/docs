To prepare the agent for your website, deploy it by [creating a Webchat v3 endpoint](#create-a-webchat-v3-endpoint). Then customize the agent to fit your needs using the [Webchat v3 endpoint settings](#configure-specific-settings).

## Create a Webchat v3 endpoint

1. In the navigation menu of the Cognigy interface, select a project.
2. In the navigation menu of the project, go to **Deploy > Endpoints**.
3. On the **Endpoints** page, click **+ New endpoint**.
4. In the **New endpoint** dialog, select the **Webchat v3** channel and click **Create endpoint**.
5. On the **Setup** tab, enter a unique name in the **Endpoint name** field.
6. In the **Target** section, select a relevant flow or agent from the list.
7. Click **Save**.

## Configure specific settings

Customize Webchat to meet your specific needs. You can adjust colors and add features such as file uploads to enhance the effectiveness of your agent. The settings are on the **Layout**, **Behavior**, **Compliance**, and **Advanced** tabs of the endpoint. Any updates you make are instantly reflected when you load or reload your website with Webchat linked to the endpoint.

#### Integration

##### Advanced layout settings

The **Advanced layout settings** provide parameters for managing the chat interface, focusing on input behavior, HTML styling, and JavaScript.

| Parameter | Type | Description |
|-----------|------|-------------|
| Remove agent message borders | Toggle | Hides the chat bubble around agent text output. Hiding the chat bubble makes agent text outputs look cleaner and fit better into the chat screen. This parameter is useful for custom designs that include system messages or long messages. It also improves the layout of interactive elements, such as buttons and links, as well as static content, such as tables. |
| Max agent output width | Number | Determines the maximum width of the agent text output as a percentage of the total available space. The default value is 73%.                                                                                                                                                                                                                                             |
| Chat window width | Number | Controls the width of the Webchat window in pixels, determining how much horizontal space it occupies on the screen. The default value is 460px.                                                                                                                                                                                                                             |
| Max auto-expanded input lines | Number | Determines the maximum number of lines that can be entered into the Reply field. If the text exceeds this limit, a vertical scrollbar automatically appears to make the input text easier to display.                                                                                                                                                                         |
| Activate input collation | Toggle | Combines typed inputs from the Reply field into a single message after a one-second delay without new text input. Immediate feedback or rapid responses are sent right away, prompting the transmission of any grouped messages.                                                                                                                       |
| Input collation timeout | Number | Enables you to specify the time delay, in milliseconds, before the agent groups together typed inputs. If users don't type anything new within this time frame, their previous inputs are consolidated into a single message. This approach ensures a complete message context, especially when users type slowly or send multiple related messages at once.                                |
| Dynamic image aspect ratio | Toggle | Ensures that images displayed in gallery, attachment, or list output types maintain their original proportions. They fill the display area width without cropping or distortion.                                                                                                                                                                                             |
| Deactivate input auto-complete | Toggle | Prevents the system from automatically suggesting or completing words or phrases for all users.                                                                                                                                                                                                                                                                 |
| Activate generic HTML styling | Toggle | Applies basic styling to HTML content within standard text messages. When you activate this parameter, the system applies a standard style to HTML code, enhancing the appearance of your text messages.                                                                                                                                                                |
| Deactivate HTML content sanitization | Toggle | Enables including JavaScript functionalities, such as `onclick` or `onload` attributes, in your HTML messages. By default, these elements are removed before the message is displayed to minimize the risk of harmful content. When this setting is activated, these elements aren't removed.                                                                       |
| Deactivate URL button sanitization | Toggle | Enables JavaScript functionalities within button or action URLs in your interface. By default, JavaScript URLs starting with 'javascript:' are blocked for security reasons. However, activating this setting preserves such URLs, allowing the embedded JavaScript code to execute when users interact with the button or element.                                           |

#### Demo Webchat settings

Demo Webchat lets you test integrations with different providers and preview Webchat's appearance before deployment. It's a valuable tool for ensuring your Webchat functions as expected before launch. To configure it, go to the **Layout** tab and open the **Demo Webchat settings** card. For more information on how to use this feature, refer to [Demo Webchat](/webchat/demo).

#### Webchat plugins

To add a link to a Webchat plugin, go to the **Layout** tab. In the **Demo Webchat settings** card, turn on **Activate Demo Webchat**, and then, in the **Webchat plugins** section, click **Add plugin URL**.
You can add multiple plugins.
For more information on creating and triggering plugins, refer to [Webchat plugins](/webchat/plugins).

##### User inactivity

The **User inactivity** settings allow Webchat to detect when an end user goes silent after a Node that expects an input, for example, [Question](/ai/agents/develop/node-reference/basic/question), [Optional Question](/ai/agents/develop/node-reference/basic/optional-question), or [Wait for Input](/ai/agents/develop/node-reference/logic/wait-for-input) Nodes. After the timeout configured in the [Enable User Inactivity Node](/ai/agents/develop/node-reference/basic/enable-user-inactivity), Cognigy.AI considers the user inactive and injects an input into the Flow with the text and data configured in this section. Use it to re-prompt the user, route abandoned conversations, or end them cleanly.

User inactivity events are written to the [Logs](/ai/agents/test/logs) page with the `[User Inactivity]` prefix.

| Parameter              | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Activate user inactivity | Lets the Enable User Inactivity Node watch for inactive users. When the user stays silent for longer than the Node's timeout, the injected text and data are sent to the Flow. When this parameter is turned off, the Enable User Inactivity and Disable User Inactivity Nodes have no effect. By default, the parameter is off. |
| Action                 | This parameter is available if **Activate user inactivity** is turned on. Defines what happens when the user is inactive. You can select one of the following options:<br/>- **Inject into current Flow** — sends the injected text and data to the Flow that the conversation is in. This option is selected by default.<br/>- **Execute Flow** — switches the conversation to the selected Flow, starting at its first Node. When that Flow ends, the user's next message starts the Endpoint's Flow again from its first Node. To return to the same Node afterward, use **Inject into current Flow** with an Execute Flow Node in your Flow instead. |
| Flow                   | This parameter appears if **Execute Flow** is selected in **Action**. Selects the Flow that the conversation switches to when the user is inactive.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Injected text          | This parameter is available if **Activate user inactivity** is turned on. Sets the text that is sent to the Flow as the user's input when the user is inactive. Leave the field empty to send data only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Injected data          | This parameter is available if **Activate user inactivity** is turned on. Sets a JSON object that is added to the input data sent to the Flow when the user is inactive. The input data always includes the `userInactivity` key with details about the timeout. Leave the field empty to send no custom data.                                                                                                                                                                                                                                                                                                                                                                                                                  |

<Accordion title="Injected input example">

Suppose you configure the following:

- Webchat v3 Endpoint:
    - **Injected text** — `The user has been inactive`
    - **Injected data** — `{"reason": "no_reply"}`
- Enable User Inactivity Node:
    - **Timeout** — `30`

The injected input object will include:

```json
{
  "text": "The user has been inactive",
  "data": {
    "reason": "no_reply",
    "userInactivity": {
      "timeoutMs": 30000,
      "consecutiveCount": 1,
      "waitingForInput": true
    }
  }
}
```

The `userInactivity` object contains the following fields:

| Field              | Description                                                                          |
|--------------------|--------------------------------------------------------------------------------------|
| `timeoutMs`        | The timeout that applied, in milliseconds.                                           |
| `consecutiveCount` | The number of inactivity inputs sent in a row without a user message in between.     |
| `waitingForInput`  | Optional. Indicates whether the Flow was waiting for an answer to a Question.        |

</Accordion>

##### Build a flow with user inactivity handling

The following example Flow asks the user whether they are ready for their order and handles a user who doesn't respond.

<AccordionGroup>
  <Accordion title="1. Configure the Endpoint">
    1. In the left-side menu of the Project, go to **Deploy > Endpoints** and open your Webchat v3 Endpoint.
    2. On the **Behavior** tab, in the **User inactivity** section, turn on **Activate user inactivity**.
    3. In the **Action** list, select **Inject into current Flow**.
    4. In the **Injected text** field, enter the text that the Flow receives when the user is inactive, for example, `You seem to have disconnected`.
    5. Optional. In the **Injected data** field, enter a JSON object, for example, `{ "reason": "no_reply" }`.
    6. Save changes.
  </Accordion>

  <Accordion title="2. Greet the User">
    1. In the Flow editor, add the [AI Agent Node](/ai/agents/develop/node-reference/ai/ai-agent).
    2. In the AI Agent Node, configure the AI Agent to greet the user, for example, with a short welcome message.
    3. Save changes.
  </Accordion>

  <Accordion title="3. Activate User Inactivity Detection">
    1. Below the **Default** Node of the **AI Agent** Node, add the [Enable User Inactivity Node](/ai/agents/develop/node-reference/basic/enable-user-inactivity).
    2. In the **Timeout** field, specify `60`. This sets the timeout to one minute.
    3. Save changes.
  </Accordion>

  <Accordion title="4. Ask the User">
    1. Below the **Enable User Inactivity** Node, add the [Question Node](/ai/agents/develop/node-reference/basic/question).
    2. In the **Question Type** list, select **Yes / No**.
    3. In the **Output Type** list, select **Text with Quick Replies**.
    4. In the **Text** field, enter `Are you ready for your order?`.
    5. Click the **Yes** quick reply and do the following:
        1. In the **Select Button Type** list, select **Postback Value**.
        2. In the **Postback Value** field, enter `yes`.
    6. Click the **No** quick reply and do the following:
        1. In the **Select Button Type** list, select **Postback Value**.
        2. In the **Postback Value** field, enter `no`.
    7. Save changes.
  </Accordion>

  <Accordion title="5. Handle the Answer">
    1. Below the **Question** Node, add the [If Node](/ai/agents/develop/node-reference/logic/if).
    2. In the **Condition** field, click **Use Advanced Editor** and enter `input.result === false`.
    3. Below the **Then** child Node, do the following:
        1. Add the [Disable User Inactivity Node](/ai/agents/develop/node-reference/basic/disable-user-inactivity). This stops the inactivity detection, so the user isn't prompted while they get ready.
        2. Below the **Disable User Inactivity** Node, add the [Say Node](/ai/agents/develop/node-reference/basic/say) and enter the text `Okay, I'll wait. Just let me know when you are ready.`.
    4. Below the **Else** child Node, do the following:
        1. Add the **Question** Node.
        2. In the **Question Type** list, select **Text**.
        3. In the **Text** field, enter `What would you like?`. This Node waits for the user's answer. If the user doesn't respond within the timeout, the injected inactivity input answers the question.
        4. Below the second **Question** Node, add the **Say** Node and enter the text `{{input.text}}`. This token outputs the injected text from the Endpoint settings.
    5. Save changes.
  </Accordion>

  <Accordion title="6. Test the Flow">
    1. Open [Demo Webchat](/webchat/demo) for your Endpoint.
    2. When the AI Agent asks `Are you ready for your order?`, select **Yes**. The AI Agent then asks `What would you like?`.
    3. Don't type or send anything for longer than one minute.
    4. Check that the AI Agent responds with `You seem to have disconnected`.
    5. On the [Logs](/ai/agents/test/logs) page, check for entries that start with `[User Inactivity]`. They report when inactivity is detected and the input is injected.
    6. Start a new conversation and answer `No`. Check that the AI Agent responds with `Okay, I'll wait. Just let me know when you are ready.` and that no inactivity message follows after one minute, because the Disable User Inactivity Node turned detection off.
  </Accordion>
</AccordionGroup>

### Advanced

The **Advanced** tab offers customization features, such as adding a watermark and activating maintenance mode for transparent communication during updates. The Webchat custom settings further enhance customization by allowing specific UI adjustments and feature integrations through JSON formatting.

#### Watermark

The **Watermark** settings let you personalize the chat interface with a watermark that suits your branding or platform,
enhancing recognition and customization options.

| Parameter | Type | Description |
|-----------|------|-------------|
| Watermark | List | Lets you select the type of watermark that appears at the bottom of the chat interface, acting as a subtle brand or platform identifier. You can select from **Default**, **Custom**, and **None**. If **Default** is selected, the Cognigy watermark is displayed. |
| Watermark text | Text | This parameter appears when the **Custom** option is selected for the watermark. This parameter enables you to specify your own text. The default text is `Powered by Cognigy.AI`.                                                                                                             |
| Watermark URL | Text | This parameter appears when the **Custom** option is selected for the watermark. This parameter lets you specify a URL as a hyperlink in the format `https://www.example.com/`. The default URL is `https://www.cognigy.com/`.                                             |

#### Maintenance

The **Maintenance** settings let you activate maintenance mode in a chat service, with options to inform users, disable the widget, or hide it. You can customize the maintenance messages displayed to users.

| Parameter | Type | Description |
|-----------|------|-------------|
| Activate maintenance mode | Toggle | Activates maintenance mode for the chat endpoint, allowing updates, feature testing, or backend work without impacting the user experience.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Maintenance mode | List | This parameter appears if **Activate maintenance mode** is activated. Determines the behavior of the maintenance mode. Choose one of the following options:<ul><li>**Inform users about maintenance mode**: keeps the chat visible, displaying a custom message about the maintenance. Best for transparency with users, maintaining engagement without full service.</li><li>**Disable the Webchat widget**: removes the chat interface from the site or app during maintenance. Best for major updates where functionality could be impacted, avoiding user confusion.</li><li>**Hide the Webchat widget**: temporarily hides the chat widget, allowing for quick accessibility post-maintenance without a page reload. Best for short or frequent maintenance periods for a quick return to functionality.</li></ul> |
| Maintenance information text | Text | This parameter applies to the **Inform users about maintenance mode** and **Disable the Webchat widget** options.<br/> It determines the text displayed to users during maintenance mode, allowing for a customizable message to inform users about the maintenance activity or any other relevant information.                                                                                                                                                                                                                                                                                                                                                                              |
| Maintenance information title | Text | This parameter applies to the **Inform users about maintenance mode** option.<br/> It determines the title displayed to users during maintenance mode, used to briefly describe the nature of the maintenance or provide a succinct message.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

#### Webchat custom settings

The **Webchat custom settings** on the **Advanced** tab offer advanced options
to change the appearance and behavior of your Webchat beyond the standard settings.
You specify these settings in the **Custom JSON** field using JSON format. Ensure the JSON is correctly formatted to prevent potential crashes of the Webchat widget.

Use the Webchat custom settings to:

- Overwrite UI text and values configured in the endpoint settings
- Change and translate UI text and [ARIA labels](/webchat/v3/accessibility#aria-labels). You can use dynamic strings, such as `{name}` or `{time}`, as described in the [embedding](https://github.com/Cognigy/Webchat/blob/main/docs/embedding.md) documentation.
- Add values from embedding files not present in the GUI
- Specify parameters for your custom Webchat version
- Use features from a later Cognigy version while using an earlier one

  <Accordion title="JSON example: change Webchat colors">

    ```JSON
        {
            "colors": {
                "primaryColor": "red",
                "backgroundColor": "red"
            }
        }
    ```

  </Accordion>

    ```JSON
                "reconnect": "Verbindung wiederherstellen",
                "ariaLabels": {
                    "messageHeader": {
                        "bot": "{name} sagt:"
                    }
                }
            }
        }
    ```
